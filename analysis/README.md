# Проверка данных для red-team review

Это исследовательский аудит исходного датасета, а не реализованный продукт и не сдаваемый role engine.

Из корня репозитория, в отдельном Python 3.12 окружении:

```text
python -m pip install -r analysis/requirements.txt
python analysis/audit_dataset.py
```

Скрипт читает только три исходных Parquet в `case/data (1)/data/` и записывает:

- `dataset_audit.json` — проверки схем, согласованности, компонент, примерных сообществ и метрик;
- `node_metrics.csv` — рассчитанные признаки всех 2248 узлов.

Исходные данные и starter не изменяются. Итоговых ролей, role_score и priority_score этот скрипт не присваивает. `cluster_id_example` — исследовательский результат Louvain с seed=42, а не утверждённые продуктовые кластеры.

Граф содержит все узлы, включая изоляты. Метрика `seed_reach_4` считает различные другие seed, из которых узел достижим по направленным путям длиной до 4 рёбер; это структурная достижимость без проверки хронологии и происхождения денег. Betweenness вычислена точно, на направленном графе, без весов расстояния. Для Louvain построена неориентированная проекция с суммой объёмов в обоих направлениях; алгоритм запускается отдельно по слабосвязным компонентам, изоляты получают отдельные сообщества. Разбиения при разных random seed не являются доказательством устойчивости отдельных кластеров.

Транзакции с одинаковыми четырьмя полями сохранены. Без transaction_id невозможно установить, являются ли они ошибочными дублями или повторными переводами. Данные сходятся с edges именно без удаления этих строк.

JSON аудита предназначен для Python/ручного анализа: его числовые GID нельзя передавать браузеру как JavaScript Number. Продуктовый API должен сериализовать gid/src/dst и списки идентификаторов строками. В CSV исходные GID сохранены десятичными целыми.

Проверки для обзора воспроизводимы на указанных версиях. Время выполнения аудита не является измерением ещё не построенного полного продуктового pipeline.
