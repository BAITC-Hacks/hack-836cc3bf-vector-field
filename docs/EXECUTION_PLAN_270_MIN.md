## Если отстаём

- **T+45 нет CSV:** Нурасыл помогает закрыть аналитические правила; остановить agent feature work. Аки продолжает на fixtures.
- **T+90 нет реального узла в UI:** Даулет и Аки соединяют один entity+subgraph; все расширения заморожены. Проверить string gid прежде всего.
- **T+120 core не Green:** все силы на пять must-have. AI откладывается, не добавляется «для галочки».
- **T+150 AI нестабилен:** ограничить одним проверяемым сценарием либо unavailable; не добавлять verifier/specialist для исправления.
- **T+180 обязательные пробелы:** исправления обязательных требований разрешены после freeze; новые возможности запрещены.
- **T+240 проблема:** отключить сломанную optional-функцию или вернуться к известной рабочей версии. Не рефакторить всё приложение.

Stretch по умолчанию выключен. Одну temporal/trace-функцию можно взять только если к T+120 все обязательные результаты уже проверены и AI не блокирует сдачу.

## Как синхронизировать ветки

Обновлённый context/contract коммит интегрировать во все три направления до расхождения схем. На своей ветке, после сохранения текущей работы:

```text
git fetch origin
git merge origin/main
```

Не делать reset --hard, не перетирать чужие изменения. При конфликте контракта сначала согласовать смысл поля, затем исправлять producer и consumers. Локальное создание/обновление ветки не публикует её автоматически; push выполнять в рамках согласованной командой публикации.

## Definition of Green

**Core Green:** три валидных CSV, 2248 узлов, documented rules, clusters, top≥20, произвольный gid и его направленные связи в UI, evidence/limitations, pipeline без AI <5 минут.

**AI Green:** один реальный вопрос с tools, проверяемые references, понятный timeout/unavailable, core не зависит от успеха LLM.

**Submission Green:** актуальный README, схема, итоговые выгрузки, исходный код, рабочий запуск на втором устройстве, репетиция, доступный репозиторий и проверенные submission links.
