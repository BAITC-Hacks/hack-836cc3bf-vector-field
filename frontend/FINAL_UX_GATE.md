## Main UX problems found

1. Технические подробности конкурировали с главным сценарием: очередь → выбранный узел → причины → граф.
2. Карточка начиналась с подробностей роли; приоритет и наблюдаемые переводы были ниже длинных списков фактов.
3. Выбор узла, ограничение графа и область вопроса Investigator требовали более явных подписей.
4. При недоступной карточке вопрос по выбранному узлу мог молча отправляться по всей сети; теперь отправка заблокирована до явного выбора контекста.

## Changes made

1. Уточнены назначение экрана, контекст выборки, очередь и выбранное состояние. Первым автоматически открывается первый узел из ответа summary, без фиксированного GID.
2. В карточке сначала показаны приоритет, причины и крупнейшие рассчитанные вклады; роль и её эвристическая оценка отделены. Полные факты, точные числа, evidence ID, источники и ограничения доступны по раскрытию.
3. Потоки собраны в компактные блоки; изолят и граница глубины имеют отдельные пояснения. Приоритет не представлен как вероятность нарушения.
4. Граф показывает направление, выбранный GID, реальные количества и скрытые результаты. Добавлены понятные действия фокусировки и расширения.
5. Область вопроса Investigator явно переключается между сетью и выбранным узлом. Контекст узла разрешён только после загрузки его карточки; недоступность AI не мешает основному сценарию.

### Проверенная проблема окружения — устранена

Первый запуск production API на `:8005` не мог прочитать `pipeline/out/top_nodes.csv` (`PermissionError` после HTTP-заголовков). Ожидалось скачивание файла, фактически соединение обрывалось; UI показал локальную ошибку экспорта без сырого JSON. Серьёзность: P1 для демо. Как и в Stage 2, повторный запуск неизменённого pipeline и API под одним Windows-пользователем восстановил скачивание; браузер подтвердил download. Изменений кода backend и ACL не было. Повторный pipeline: 9.736 с, 2248 узлов, 105 кластеров.

## Recommended demo path

Основная репетиция — без AI:

1. Открыть экран: показать назначение, контекст июля 2026 и первый выбранный узел очереди.
2. В поиске полного GID ввести `100000003115284100`, выполнить поиск. Показать «Почему проверить этот узел», крупнейшие вклады и отдельную гипотезу роли.
3. Раскрыть «Проверить расчёт приоритета»: показать совпадение суммы вкладов, точный факт и источник. Свернуть детали.
4. Найти `100000007908818100`. На графе показать выбранный узел, стрелки и 11 узлов / 11 рёбер; нажать «К выбранному», затем «Всё окружение».
5. Нажать «2 узла»: показать предупреждение и скрытые 9 узлов / 10 рёбер. Нажать «Расширить окружение до 200 узлов»: снова 11/11.
6. Найти `100000000018102100`: объяснить, почему глубина 4 ограничивает вывод о конечном получателе. Затем `100000000456947100`: отсутствие наблюдаемых связей — корректное состояние данных.
7. Вернуться к основному графу; через меню CSV скачать `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv`.
8. При необходимости показать unavailable Investigator: основная аналитика остаётся доступной. Не выдавать это за демонстрацию ответа модели.
